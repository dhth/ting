# ting

`ting` provides audio feedback on the command line for exit codes and named cues. It is a single Rust binary with built-in success/error sounds and optional TOML configuration for custom MP3 and WAV files.

This project uses `mise` for tool management and tasks. Always use `mise` to execute project commands; see `mise.toml` for available tasks. Linux builds require ALSA development libraries, declared in `mise.toml` and installed with `mise bootstrap packages apply --yes`.

```text
CLI arguments + configuration → playback data → sound selection → audio playback
```

- `src/args.rs` defines the clap interface and debug output.
- `src/main.rs` dispatches commands, prints results, and controls process exit codes.
- `src/config` defines the TOML model, discovers the platform-specific config path, and loads configuration.
- `src/domain` combines play arguments and configuration into `PlayData` and `PlayBehaviours`, including reading custom sound files into memory.
- `src/cmds` selects built-in or external sounds, invokes playback, and implements config sampling and validation. Embedded sounds and the sample config live in `src/cmds/assets`.
- `src/audio` owns rodio decoding and blocking playback through the default output device.
- `src/utils.rs` provides shared `~/` expansion.

Keep clap and process-exit concerns at the CLI boundary and rodio/device concerns inside `audio`. Pass prepared playback data into `cmds::play` rather than making the audio layer interpret arguments or configuration. Prefer pure transformations and explicit inputs and outputs where practical, while keeping the code idiomatic to Rust; local mutation is fine when clearer.

Prefer integration tests for user-visible CLI behavior using `tests/common::Fixture` and inline `insta-cmd` snapshots of stdout, stderr, and exit status. The fixture sets `TING_TESTING=1`, which reports sound selection without opening an audio device; configuration and custom-file reads still happen. Use explicit fixture config paths rather than depending on the developer's config. These tests do not verify audio decoding or actual playback.

`.github/workflows/release.yml` is generated by cargo-dist. Change release configuration in `dist-workspace.toml` and build setup in `.github/build-setup.yml`, then regenerate with `dist generate` rather than hand-editing the generated workflow.
